# Soul Shards Forever: architecture map

Generated by tools/check.py from the toc order, the file headers (the job line) and the
code of Core and the modules (every SendMessage, RegisterMessage, RegisterEvent and
RegisterBucketEvent there; the widgets send and register none). Do not
edit by hand: fix the header or the code and rerun the check. A file or message missing
here is missing from the headers or the code, not from this file.

## Files, in load order

Each file's job line, then what it offers the others (its header's Public).

Widgets (custom AceGUI widgets, used from the options table through dialogControl, or
created by Window and by each other):

- Widgets\SSFStepperSlider.lua: the stock AceGUI Slider with a "-" button and a "+" button framing the value box under the bar, for fine tuning after a rough slide, and an optional bound the thumb cannot pass.
  Public: the Slider's: SetLabel, SetSliderValues, SetIsPercent, SetValue, GetValue, SetDisabled; SetCustomData(arg) (AceConfigDialog hands the option's `arg` to it): a number or a function is the bound; a table is { bound = the same, released = function(value), notches = true, busy = function(), ends = { low = text, high = text } }, each optional; MinWidth() -> the narrowest it stays usable, its label on one line or the "-", box, "+" row, whichever is wider (SSFFrame:FitWidth sizes the window to it). The min and max labels and the "-", box, "+" row start UNDER_BAR below the bar (the stock Slider starts the labels inside it), so the thumb at either end, a notch tick and the bound's tick never run into a label or a button. Each label is centered under the place the thumb rests at that end, not at the bar's corner.
- Widgets\SSFSideNote.lua: a note panel beside the options window, level with its top.
  Public: AttachTo(frame, gap, look) -- the window's frame; called once by SSFFrame. look: what the note copies from the window so the two panels read as one, each a number the window owns: shade (its SHADE, laid as black inside the note's border), helpArt and helpCrop (its help button's art and crop, for the copy of the "i"), buttonHeight (its bottom buttons'), rounding (its px added to a measured width, for the tick box's label), halfLine (SSF's half line of empty space, px: the extra air between a divider and the text in the plain layout); and where and what this note is: side ("LEFT": on the window's left; anything else: its right), plain (true: the plain layout). Show(title, body, note, opts, titleColor) -- opts, all optional: lead (the gold line under the body's divider, with its own divider), blocks (a list of { text } paragraphs and { text, macro = true } macros; either with blank = true has one blank line of its own font under it), button and onClick (a button as wide as its text; onClick runs on the click, before it, and a slash command it returns then runs as the click through the game's secure path, so /reload from it can't be blocked), buttonNote (a small line just above the button: what a click does), buttonDisabled (greys the button), onClose (called once when the note closes). titleColor: { r, g, b } or nil. The plain layout reads title, blocks, button, onClick and onClose, and: tick (the tick box's label), ticked (true: the box starts ticked; every Show sets the box from it, so an owner that fills an open note again, such as after a Language change, keeps the player's tick only by passing it back: NewsShow saves it through onTick and reads it again), onTick (called with ticked, on every tick and untick), buttonTicked (the button's label while ticked). body, note, lead and buttonNote are not drawn there. Layout(windowWidth) -> the note's width; SSFFrame calls it when the window's width changes. Close() -- hide and tell the owner once. Showing or not is AceGUI's own IsShown.
- Widgets\SSFFrame.lua: SSF's options window, an extension of AceGUI's stock Frame container.
  Public: the stock Frame's SetTitle, SetStatusTable, Show, Hide; FitWidth() -> changed, FitToContent(), SetTitleColor(r, g, b), SetTitleBand(alpha), SetActionButton(text, onClick, tipText), SetMiddleButton(...), SetRightButton(text, onClick, tipText), SetHelpButton(onClick, isOn, tipText), ShowSidePanel(title, body, note, opts) and ShowLeftPanel(title, opts) (opts as SSFSideNote:Show; the right note and the left one), MakeRoom() (a showing note that would hang off the screen sends the window to the center; the owner calls it after every feed, which is where the saved spot comes back and the width changes), SetFooter(text). Callback: "OnMoved"(top, left).
- Widgets\SSFCentered.lua: two AceGUI widgets that reposition their stock counterpart, for use from the options table through `dialogControl`.
  Public: SSFCountButton: SetText, SetCustomData(getText), SetDisabled, MinWidth(); SSFIndentCheckBox: the CheckBox's SetLabel, SetValue, GetValue, SetTriState, SetDisabled, SetDescription, SetType, SetImage; SetCustomData(level, or { level, radio, after, follows }); MinWidth(). MinWidth() is the width the text needs on one line, which SSFFrame:FitWidth sizes the window to.

Core and modules:

- Core.lua: the addon object, the warlock gate, the saved settings (the AceDB profile, its defaults and the migrations of old values), the Language switch (ApplyLanguage) and the shared constants on the addon object.
  Public: SSF.SHARD_ITEM_ID; SSF.SPELLS (the spell ids SSF names, by key); SSF.HALF_LINE (px: SSF's half line of empty space, the one spacing unit its widgets share); SSF.ICON, SSF.VERSION and SSF.AUTHOR (each from the toc); SSF.db (AceDB), SSF:ApplyLanguage() (Options' Language setting calls it, then rebuilds).
- Modules\Colors.lua: every color SSF uses, and the helpers that paint text with them.
  Public: Colors.RED, GREEN, YELLOW, GOLD, WHITE, DIM, ECHO, BLUE, CODE, SLATE, BLACK -> { r, g, b, hex } Colors:ForState(state) -> r, g, b, hex for "low" / "ok" / "over" / "paused" / "quiet"; any other state is an error (as in PaintState) Colors:Paint(color, text) -> text wrapped in the color's escape codes Colors:PaintState(state, text) -> text in the state's color Colors:Value(v) -> v in white (a setting's value) Colors:Accent(v) -> v in green (branding) Colors:OnOff(b) -> green ON / red OFF Colors:State(text, good) -> text in green (good) or red Colors:Gold(text) -> text in the label gold Colors:Echo(text) -> text in the command echo grey Colors:Code(text) -> text in the code color (a macro shown as text) Colors:Commands(text) -> text with each command it names (/ssf delete, /stopattack, /stopcasting) in the code color; the rest untouched Colors:Class() -> r, g, b of the warlock class color (titles only)
- Modules\Combat.lua: the two questions SSF asks about a fight, each answered here and nowhere else.
  Public: Locked() -> bool; InFight() -> bool. Owns no state, no events, no frames.
- Modules\KeyBindings.lua: SSF's two rows in Blizzard's Key Bindings screen (Bindings.xml: SSF_DELETE and SSF_PAUSE), unbound until the player picks keys.
  Public: KeyBindings:ApplyLabels() (Core:ApplyLanguage calls it after a language switch) KeyBindings:Open() (the window's Key Bindings button; the caller closes the window first, SSF's window draws above the settings panel)
- Modules\Bags.lua: read-only queries over the player's bags, backpack through the reagent slot (bag 5, where a soul pouch equips on Forever), and the one signal that the bags changed.
  Public: NumSlots(bag) -> n; IsShardAt(bag, slot), IsFreeAt(bag, slot), IsLocked(bag, slot), IsSwappableAt(bag, slot), IsSoulBag(bag), IsRegularBag(bag), HasSoulBag() -> bool; SoulBags() -> ids ascending; SortOrder() -> ids in sort order; ForEachSlot(fn(bag, slot, position), topFirst); ForEachShard(fn(bag, slot)); Count() -> n; SoulBagSlots() -> n; AnyShardLocked() -> bool; LastShard(topFirst) -> bag, slot or nil. Every one is also the headless tests' handle on the bags.
- Modules\Cap.lua: the thresholds, and whether Drain Soul is known (the quiet state).
  Public: Cap.MIN, Cap.MAX, Cap.QUIET_UNTIL (the spell id); Get() -> cap, IsAuto() -> bool, LowMark() -> the low mark (never above the cap), SetLowMark(n) (Options' slider: held between MIN and the cap), State(count) -> "paused" | "quiet" | "low" | "ok" | "over" (for a color or a glow: Colors maps them, LowGlow compares "low"; no delete, sort or setting is decided by comparing these words), IsOver(count) -> bool (over the cap: a press would delete), IsFull(count) -> bool, IsQuiet() -> bool, SetManual(n) (Options' slider and /ssf setmax; turning AutoMax off is the caller's job), Recompute().
- Modules\Sorter.lua: one pass moves shards into free soul bag slots (SSF Mode): every shard that sits in a later bag than a free soul bag slot (Bags header order) is picked up, dropped into that slot, cursor cleared.
  Public: Pass() -> moves fired (0 while paused or in combat); TopFirst() -> true under SoulSort legacy Normal.
- Modules\Sounds.lua: SSF's own sounds: in LibSharedMedia's "sound" list, playing one by its LSM name, and what a volume level means.
  Public: Play(name, volume) -- an LSM sound name and a volume 0-1 (nil = full). A name LSM no longer knows (a sound pack removed) falls back to the default; a nil name plays nothing (LSM:IsValid is true for nil). PlayPause() -- the pause sound at the saved notch (profile.pauseSoundName, pauseSoundLevel), nothing at notch 0: a paused press out of combat (Trimmer decides when) and the slider's preview. Busy() -> true while an own sound plays (a play asked for now would be silent). DefaultName() -> the default sound's LSM name (Core's profile default). LevelStep() -> the distance between two notches (the slider's step; its scale is 0 to 1); LevelVolume(level) -> the volume a notch plays, 0 for notch 0 (a number between two notches plays as the nearest); LevelFromOld(on, volume) -> the notch for the two values saved before the slider (volume nil = the old default, full; a volume that was no level = full, the old rule).
- Modules\MoveSounds.lua: whether the game's item sounds are heard around SSF's own shard moves.
  Public: Moving(kind, fn) -- runs fn, which moves or deletes shards; kind is "sort" or "delete" (Sorter and Trimmer hand their moves over and know nothing of the rule). Returns nothing, heard or not.
- Modules\Trimmer.lua: the delete press.
  Public: Delete(); Paused() -> bool, the one pause gate (Sorter:Pass asks it too); WhyNot(count) -> why a press would not delete, or nil if it would: "paused" (a mode: the only answer while paused, whatever the count), "quiet" (no Drain Soul yet, Cap:IsQuiet), "atcap", "undercap", "locked" (over the cap, but the server still holds a shard). The window's Delete Shard button greys on it with the reason under it. No combat reason: a press deletes in a fight too, and the window is shut in one.
- Modules\DeleteButton.lua: the global button "SSFDelete".
- Modules\Debug.lua: the debug record.
  Public: IsOn() -> bool; Set(on) (turns the record on or off and records that); Mark(name) (a marker; turns the record on first when it is off); Clear() (empties the saved record; the switch stays as it is); Log() -> the saved list of events (the tests' handle); Text() -> this session's events as text, one line each under two heading lines: every event since the record was first turned on after the last login or reload.
- Modules\DebugReport.lua: the window a player copies the debug record from.
  Public: Open() (opens the window, or refills it when it is already up).
- Modules\Settings.lua: turns ONE definition of a stateful setting into the two AceConfig entries it needs: a GUI control (toggle or range, hidden from chat) and a chat command (hidden from the GUI) that share the same get/apply.
  Public: Settings:Define(key, def) where def = { order, kind = "toggle"|"range", name, desc, get(), apply(value), optional extra() -> text appended to the chat echo, optional echo() -> the whole echo line in place of "name: value" (pause), optional disabled, and for range: min, max, step }. Returns gui, cmd -- two entries for Options to place in its args table; a GUI-only setting places gui and drops cmd. cmd.set(info, input, short): short = true when the player typed a range's number with no key ("/ssf 25", Options' handler): the range check is still this module's, and a bad value's usage line comes back in that short form ("Use: /ssf <min>-<max>"). AceConfig's own set takes (info, value) only: short is SSF's, and only a caller that runs the command from code passes it. Settings:ValueWords(key) -> the words a toggle's chat command takes ("off", "on"), nil for a range or an unknown key: TabComplete offers them after the key.
- Modules\Help.lua: help mode.
  Public: IsOn() -> bool, Toggle(); Apply(root) (Options, at the end of every build); KeepHover(widget, wrapper, innerFrames) (a widget's constructor: wrapper is the widget's own frame, innerFrames the stock frames that take the mouse while enabled), Greyed(widget, disabled) (the widget's SetDisabled, after the stock call).
- Modules\Options.lua: the one settings table.

- Modules\DebugCommand.lua: the words after "/ssf debug".

- Modules\SlashCommand.lua: /ssf itself.

- Modules\TabComplete.lua: Tab in the chat box, through AceTab.

- Modules\Status.lua: the one wording for every number SSF shows and every status line it prints.

StatusText(count, cap) -> "Soul Shards: N (cap M)", chat (a bare /ssf, the login lines, the announce line, the paused-press line). ## Shared state and exceptions

The AceDB profile is the one shared state: any module may read it, only its owner derives
a rule from it (CLAUDE.md). NS is the addon-private table Core and the locale registrar
share.

The documented exceptions to the two rules, 5 in all, from each header's Exceptions:

- Core: ApplyLanguage rewrites the AceLocale table in place, repeating AceLocale's two rules (enGB is enUS; a `true` value in the default means the key is the string). AceLocale has no runtime switch: NewLocale keeps only the default and the client's locale (GAME_LOCALE, when set, stands in for the client's), so the Language setting can only be done by writing into the table every module holds.
- Counter: the FontString and the backing texture are raw: AceGUI builds widgets inside its own windows and cannot draw on a Blizzard button. One of the exceptions CLAUDE.md lists.
- DeleteButton: a raw, named CreateFrame. /click resolves a GLOBAL frame name, and AceGUI widgets are pooled frames meant for windows, unnamed or named by a counter, so a raw frame with a fixed name is the only way to give /click a target. One of the exceptions CLAUDE.md lists.
- Window: the title strip behind each group title is a raw frame: AceConfigDialog hardcodes the InlineGroup widget, so there is no Ace way to add one. One of the exceptions CLAUDE.md lists.
- SSFFrame: the frame gets a global name (FRAME_NAME) so UISpecialFrames can close it on Escape; the stock Frame is unnamed and Escape has no other way in.

Library internals are read in: Core, Help, Tooltip, Window, SSFCentered, SSFFrame, SSFSideNote, SSFStepperSlider. Each header's "Lib internals"
names the fields and what breaks when a library moves them.
